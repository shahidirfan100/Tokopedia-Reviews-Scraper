# API Discovery Notes

This actor uses Tokopedia GraphQL endpoints discovered from Tokopedia review-page JS bundles and validated by direct request replay.

## Selected Endpoints

- `POST https://gql.tokopedia.com/graphql/productReviewList`
    - Query: `productReviewList`
    - Purpose: fetch paginated product reviews

- `POST https://gql.tokopedia.com/graphql/productReviewFilterSummary`
    - Query: `productReviewFilterSummary`
    - Purpose: fetch available review filter keys (media, ratings, topics)

- `POST https://gql.tokopedia.com/graphql/getMiniProductInfo`
    - Query: `getMiniProductInfo`
    - Purpose: resolve/validate product metadata from product URL

- `POST https://gql.tokopedia.com/graphql/SearchProductV5Query`
    - Query: `SearchProductV5Query`
    - Purpose: keyword-to-product fallback resolution

## Request Pattern

All endpoints are called with `POST`, `content-type: application/json`, and these endpoint headers:

- `origin: https://www.tokopedia.com`
- `referer: https://www.tokopedia.com/`
- `x-source: tokopedia-lite`
- `x-tkpd-lite-service: zeus`
- `x-device: mobile-0.0`
- `x-dark-mode: false`

The browser fingerprint headers (`user-agent`, `sec-ch-ua*`, `accept*`) are generated by the
selected Impit profile and must not be overridden manually.

## Impit Browser Profile Compatibility

Tested live against `productReviewList` (3 attempts per profile, product `100018999468`):

| Profile                                                                                                                                    | Result                                         |
| ------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| `chrome`, `chrome100`, `chrome101`, `chrome104`, `chrome107`, `chrome110`, `chrome116`, `chrome124`, `chrome136`, `chrome142`, `chrome151` | Works                                          |
| `firefox133`, `firefox135`, `firefox144`                                                                                                   | Works                                          |
| `ios18`                                                                                                                                    | Works                                          |
| `chrome125`, `chrome131`                                                                                                                   | HTTP/2 stream reset (`INTERNAL_ERROR`, Remote) |
| `firefox`, `firefox128`                                                                                                                    | HTTP/2 stream reset (`INTERNAL_ERROR`, Remote) |
| `okhttp`, `okhttp3`, `okhttp4`, `okhttp5`                                                                                                  | HTTP/2 stream reset (`INTERNAL_ERROR`, Remote) |
| No `browser` option (default)                                                                                                              | Request timeout                                |

Conclusion: Tokopedia's edge TLS/ALPN handling resets HTTP/2 for some fingerprints. A browser
profile must always be pinned, and the actor rotates through known-good profiles before falling
back to HTTP/1.1.

## Resilience Strategy

1. Primary profile: `chrome`. Rotation list: `chrome`, `chrome136`, `chrome124`, `firefox133`, `ios18`.
2. On an HTTP/2 reset, the actor rotates to the next known-good Impit profile (one shared instance
   per profile, reused across requests).
3. If every profile is reset, it switches the run to HTTP/1.1 via `undici` with mobile-web headers.
4. Non-JSON/challenge responses are treated as retryable and trigger a profile rotation.
5. Network errors, timeouts, `429`, and `5xx` are retried with bounded exponential backoff + jitter,
   honoring `Retry-After`.

## Product URL Handling

The actor accepts one input, `product_url`, and normalizes it before resolution:

- trims surrounding whitespace;
- prepends `https://` when the scheme is missing;
- accepts any `tokopedia.com` host (with/without `www`, `m.`, uppercase, `shop-id.`);
- keeps the path, drops the query string and fragment;
- strips a trailing `/review` and trailing slashes.

Product resolution order:

1. `getMiniProductInfo` with the normalized URL returns the canonical product ID and metadata.
2. If that endpoint answers `Not Found` (some newer or Shop-PDP products), the actor falls back to
   the numeric identifier parsed from the URL path.
3. If no identifier can be resolved, the run fails with a clear message instead of pushing empty data.
4. Delisted products (for example HTTP `410 Gone`) resolve nowhere and fail with
   "Product not found or no longer available at the provided URL."

Verified live URL forms: standard, `/review`, trailing slash, query parameters, missing scheme,
missing `www`, `http://`, `m.tokopedia.com`, uppercase host, surrounding spaces, slug-only
(no numeric suffix), and `shop-id.tokopedia.com/pdp/...`. All resolved and returned reviews except
genuinely delisted products.

## Validation Result

- Endpoints return HTTP 200 with valid review payload for live product IDs.
- Actor implementation is API-based (no HTML parsing for review extraction).
- If product metadata endpoint is temporarily unstable, scraper falls back to product ID parsed from URL when possible.
